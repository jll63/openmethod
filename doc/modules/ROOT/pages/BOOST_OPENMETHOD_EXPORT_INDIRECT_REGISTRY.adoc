
# BOOST_OPENMETHOD_EXPORT_INDIRECT_REGISTRY

Exports the state of cpp:indirect_registry[] from the module that owns it.

## Synopsis

May be defined by a program before including
`<boost/openmethod/default_registry.hpp>` (directly, or via
`<boost/openmethod.hpp>`), in _exactly one_ translation unit of the module
that owns the registry.

## Description

Same as
xref:BOOST_OPENMETHOD_EXPORT_DEFAULT_REGISTRY.adoc[BOOST_OPENMETHOD_EXPORT_DEFAULT_REGISTRY],
but for cpp:indirect_registry[], which has its own state. Client modules use
xref:BOOST_OPENMETHOD_IMPORT_INDIRECT_REGISTRY.adoc[BOOST_OPENMETHOD_IMPORT_INDIRECT_REGISTRY].

IMPORTANT: if the owning module has more than one translation unit, each of the
others must define `BOOST_OPENMETHOD_DECLARE_EXPORT_INDIRECT_REGISTRY` instead,
before including the same header. It emits an _exported explicit instantiation
declaration_, which both suppresses implicit instantiation and pins the symbol
to default visibility. Without it, those translation units instantiate the
state implicitly; under `-fvisibility=hidden` that copy is module-local, and
since ELF merges COMDATs at the most restrictive visibility the whole symbol
becomes local and clients fail to link. A module with a single translation unit
needs only this macro.

See xref:shared_libraries.adoc[Shared Libraries] for a full discussion.
